# 大单打板队列撤单跟踪

这是从 `large_order_limit_up_buy` 当前原生 Python 脚本复制出的独立策略目录。实现修改只落在本目录，不覆盖原打板策略，也不自动部署到 QMT。

入口文件：`QMT_LARGE_ORDER_LIMIT_UP_QUEUE_TRACKER.py`，编码为 GBK，运行于 QMT 原生 Python 模型环境。

## 逻辑

- 主单只由单笔涨停价买入大单触发，阈值为超过 90 万股或超过 500 万元。首封仍检查日内低点低于开盘价的 98.5%。首次回封要求上一轮封板超过 10 秒、封单峰值至少 1 亿元，且开板满 3 秒。零成交撤单后的重试不再检查封板时长和封单峰值，直接等待开板、再等待回封；开板满 3 秒和新的合格大单触发仍保留。有效连续竞价盘口的买一价等于当天涨停价且买一量大于零时，记为涨停封板。盘口确认离开涨停价或涨停价买一量归零时，记为开板。盘口字段不足以确认时保留最近一次判定。汇总同时显示盘口和下单流程状态。处于 READY 的股票也记录封板时长和封单峰值，合格封板开板后可进入 WAIT_RESEAL。
- 大单触发后先提交主单；主单 `passorder` 未明确返回失败时，立即提交一手（100 股）当日跌停价买入哨兵单，不等待异步委托回报或主单委托号。
- 从触发事件开始按 `l2order` 到达顺序收集事件，触发单本身计入集合。集合只记录涨停价买单，按顺序打印委托数量（股）；委托号留在内存中用于撤单跟踪，不写进数量列表。
- 哨兵以买入方向、100 股、当日跌停价识别，识别后结束采集并请求撤销哨兵委托。跌停价只读取日期明确匹配运行日的 QMT instrument detail 或行情字段，不根据昨收自行估算；日期不匹配或取不到时跳过哨兵单，采集使用 1 秒事件时间兜底。
- 兜底窗口截至触发事件时间加 1 秒，在首条超过截止时间的 `l2order` 事件到达时结束。采集阶段不做新鲜度过滤。若行情流没有推进到截止时间，收盘停止策略时会输出已有集合；哨兵未更早遇到边界时，在哨兵提交后 1 秒标记待撤。
- 集合边界确定后，跟随验证只使用本次采集集合，不再统计下单后的 `l2order` 事件。筛选单笔金额严格大于 100 万元的订单并累计金额；累计额严格大于 `QUEUE_FOLLOW_VERIFY_MIN_TOTAL_AMOUNT`（默认 1000 万元）时保留主单，否则立即请求撤单。合计金额恰好等于阈值也判定失败；无法建立集合时也按验证失败处理。
- 对集合中有委托号的订单跟踪撤单：使用 `l2order` 撤单事件；深市同时接受 `tradeFlag=3` 且 `buyNo` 命中集合委托号的 `l2transaction` 撤单事件。沪市依赖 `l2order`。集合委托仍待跟踪时，主单结束不会提前退订深市 transaction 流。
- 哨兵或 1 秒兜底完成集合后，按集合原始委托股数计算撤单比例：分母包含触发单，以及哨兵边界前采集到的涨停价买单（如果已采到，也包含我方主单）；分子按每笔委托的累计撤单股数统计，并封顶在该笔原始委托量。累计撤单股数严格超过集合总股数的 50% 时，触发本轮主单撤单。单独的触发大单撤单只记录。
- 队列金额验证失败或队列撤单比例过线后，等待券商确认主单零成交撤单以及旧哨兵单结束。之后用新行情回到 `WAIT_REOPEN`；如果新行情已经显示开板，直接进入等待回封。零成交撤单后的重试跳过封板超过 10 秒和封单峰值至少 1 亿元的要求，但仍等待开板满 3 秒及新的合格大单触发。补单按新金额规则重新验证、发哨兵单并采集队列。主单有成交时按原流程撤剩余量，结束该股的补单流程。旧哨兵状态未确认时继续等待。
- 每次实际状态切换都会打印 `[状态] 股票代码(名称) 旧状态 -> 新状态 reason=原因`，相同状态不重复打印，便于按时间线复盘。
- 有效盘口的封板 / 开板变化会打印 `[盘口状态] 股票代码(名称) 旧盘口 -> 新盘口`，并包含买一价、买一量、涨停价和行情事件时间；盘口状态未变化时不重复打印。

## 实盘边界

副本沿用源策略的 `ENABLE_LIVE_ORDERS=True` 和账户配置。哨兵单是实际委托，并会在识别到边界、超时或兜底完成后尝试撤销；回报无法关联或撤单重试耗尽时会记录异常日志。当前工作仅创建仓库副本，不部署或启动策略。

源策略的股票池内容和 `POOL_TRADE_DATE` 也保持原样，独立试运行前需要按新策略的候选池更新。

主单每次成交回报打印当时已收到的队列撤单笔数、股数、按股数计算的比例及撤单阈值。统计包含触发单，与策略撤单口径一致。采集尚未完成时显示待确认。
