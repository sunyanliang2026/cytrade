# 设计映射

本文把 `strategies/large_order_limit_up_buy/docs/design.md` 中的需求映射到当前原生脚本。原设计文档仍是策略规则的来源；本文件记录原生实现的边界和尚未完成的部分，避免后续迭代把“已实现”和“待实现”混在一起。

## 运行结构

`init(C)` 校验内存股票池的交易日、创建每只股票的独立实例、取得初始行情、建立订阅并启动定时器。策略允许在交易日盘中任意时间启动：竞价窗口内使用有效竞价快照，连续竞价中启动则以第一条有效 `l2quote` 判断当前是否已封板。行情回调按股票代码闭包分发到实例；`handlebar(C)` 负责验证定时器兜底和周期汇总；`stop(C)` 取消任务并清理订阅。

全局 `_INSTANCES` 是跨回调状态的唯一容器。实例保存涨停价、昨收、开盘价、当日最低价、封板周期、大单去重集合、行情订阅号、订单号和验证状态。回调入口先用有绝对日期且具备亚秒精度的 `time`/`stime` 做新鲜度闸门；不合格事件只更新计数并按频率限制输出诊断，不保留原始行情。通过闸门后只对顶层字典和盘口数组做轻量脱离，再更新策略状态和统计数据，避免高频回调执行递归 `deepcopy`。

## 状态机

```text
WAIT_INITIAL_QUOTE
  ├─ 09:25 快照买一=涨停价 -> WAIT_REOPEN
  ├─ 09:25 快照买一<涨停价 -> READY
  └─ 快照无效 -> 保持 WAIT_INITIAL_QUOTE，等待有效 L2 quote

READY
  ├─ 原首封路径：买一涨停、封单>6000万、涨停大单累计>1000万、开盘后低点<开盘价*0.985
  │    -> 首封下单
  └─ 单笔涨停价买入委托量>9000手或金额>500万元，且开盘后低点<开盘价*0.985
       -> 在当前 l2order 回调立即提交首封大单委托

WAIT_REOPEN
  └─ 封板>10秒且峰值>=1亿元，开板>=3秒后再次封板
       -> 原回封路径下单并进入验证

WAIT_RESEAL
  └─ 合格开板持续>=3秒后，收到单笔涨停价买入委托量>9000手或金额>500万元
       -> 立即回封大单下单

策略下单条件满足 -> 首封/回封委托进入提交流程
  ├─ 决策前最近2秒（最多200笔）已有2笔不同委托各>=150万元
  │    -> 本次委托照常提交；不因跟随观察不足请求撤单
  └─ 前置历史不足2笔 -> passorder前启动跟随观察，随后照常提交
       ├─ 观察到2笔不同委托各>=150万元 -> 保留委托，不撤单
       └─ 先满150笔或1秒到期仍未满足 -> 请求撤销未成交部分
```

上述单笔大单路径是原首封和回封路径的附加入口，不替代原累计首封条件或原 quote 回封条件。原首封委托也接入同一验证器；撤单后补充追随委托不重复验证。

首封单笔大单路径同样要求开盘后低点低于开盘价的 98.5%。盘中启动时，初始快照会先初始化开盘价和日内低点；盘前启动时，日内低点由开盘后的连续竞价 `l2quote` 更新。单笔大单阈值由当前 `l2order` 回调触发，回调直接检查已缓存的开盘价和低点，条件满足即提交，不等待下一轮约每 3 秒到达的报价。报价只维护该过滤条件，不承担单笔大单触发。低点条件尚未满足或数据不可用时，该笔委托不触发下单。

### 首封/回封下单与验证时序

1. **先记入候选历史。** 连续竞价的 `l2order` 回调先过滤为精确涨停价买入委托，再按委托号或事件键去重并保存到该股票的历史队列。队列最多保留最新 200 条，记录事件时间、本机单调接收时间、委托号、数量和金额；超出上限时丢弃最旧记录。卖单、非涨停价委托、重复事件和连续竞价以外的事件不进入该队列。
2. **确定下单决策时点 D。** 首封大单、累计首封、回封大单或 quote 回封路径确认下单，并通过账号、数量及实盘开关检查后，`_submit` 创建本次委托 token。验证器在此时记录决策时间 D。单笔大单触发路径把触发委托的 `event_key` 传给验证器，保证它不会被当作跟随委托。
3. **在 `passorder` 前回溯历史。** 验证器从最多 200 条候选记录中选出本机接收时间距 D 不超过 2 秒、事件时间有效且不晚于 D 的记录；缺失事件时间、超出 2 秒或事件时间晚于 D 的记录排除。前置候选记录中，金额不低于 150 万元且委托键不同的委托计作大单。找到 2 笔不同的大单，只表示已有足够跟随证据，本次委托不会因后续观察不足而触发撤单；这项检查不改变原有下单条件，也不阻止委托提交。
4. **启动撤单判定并异步提交。** 若前置历史不足 2 笔，前置记录仍计入验证笔数和 150 笔上限，验证器设定本机 1 秒截止时间；随后照常调用 `passorder(..., quickTrade=2, ...)`。验证状态在 `passorder` 前建立，不等接口返回、委托号绑定或委托回报；它只决定之后是否请求撤单，不是下单许可条件。`passorder` 被明确拒绝或调用抛出异常时，停止该次验证。
5. **只把 D 之后的新委托作为后续观察。** 后续 `l2order` 必须是去重后的涨停价买入委托，且事件时间严格晚于 D；缺失时间、时间不晚于 D、触发委托，以及委托号已关联为本策略委托的事件不计入。单笔金额不低于 150 万元的不同委托累加为跟随大单。前置记录与 D 之后的有效记录合计达到 2 笔不同大单时立即通过，委托继续有效。
6. **未通过则撤销未成交部分。** 尚未找到 2 笔跟随大单而有效验证笔数达到 150，或本机单调计时达到 1 秒截止时，验证失败并请求撤销未成交数量。若委托号尚未回报，先保存待撤意图，再通过有界查单或唯一匹配的异步回报补齐委托号后撤单；不按账户最新委托盲目关联。订单回报只负责委托状态与委托号关联，不作为开始验证的条件。

事件时间用于判别连续竞价、划分 D 前历史与 D 后观察；2 秒回溯年龄、1 秒验证期限及待报提醒使用本机单调时钟或 QMT 定时器，不用行情时间戳计算经过时长。

## 行情订阅与输入

当前策略实时只订阅 `l2quote` 和 `l2order`。启动时仍通过 `get_full_tick` 取得一次行情快照，但不建立 tick 实时订阅。`l2quote` 立即订阅；09:30:20 前不申请 `l2order`，之后由新鲜有效报价中最新价相对昨收涨幅严格大于 7% 触发，开板或跌回阈值以下继续保留，原负收益退出和停止清理仍有效。窗口定时任务只检查仍新鲜的候选，盘中启动也按有效快照或报价选择，不对全池订阅。订阅判断先于业务早筛，使用独立价格时间水位；不改变原下单及跟随验证逻辑，不增加等待逐笔首条或统一下单时间闸门。详见 [动态订阅设计](DYNAMIC_L2ORDER_SUBSCRIPTION_DESIGN.md)。`l2quoteaux`、`l2transaction`、`l2transactioncount` 和 `l2orderqueue` 不参与策略判断，改由独立诊断探针按需订阅。决策入口只接受新鲜、有效且未乱序的事件：`l2quote` 最多允许 3 秒，`l2order` 最多允许 2 秒；启动前已在队列中的旧事件和乱序事件只计数，不进入状态机或保存原始数据。通过时间闸门后，`l2quote` 还必须处于连续竞价并能更新涨停盘口、负收益或开盘低点；`l2order` 只保留连续竞价内的涨停价买入、有效数量且去重后的委托。无效入口按 `entry_drop` 周期汇总，不执行额外复制或原始数据缓存。缺少绝对日期或亚秒精度但时段可解析的事件只更新 `freshness_drop` 并输出低频诊断，不影响策略状态，延时记为不可用。策略不读取股票池文件、不写日志或行情文件，也不通过网络连接外部程序。

策略判定使用三类数据，各自职责固定：

- `l2quote` 维护连续竞价最新报价、昨收对比、当日最低价和涨停盘口状态；连续竞价期间最新价低于昨收时，股票退出监控并取消自己的行情订阅。
- `l2quote` 只负责封板状态、买一封单量和涨停价比较；封板只比较 `bid1` 与精确涨停价，封单金额按 `价格 * 手数 * 100`。
- `l2order` 的 `volume` 按股计算，委托金额优先取事件 `amount`，缺失时按 `price * volume` 计算，不再乘 100。它负责原累计首封、单笔大单首封/回封、验证和委托去重。
- 新鲜度闸门在载荷复制和策略判定之前执行；不把开盘时 QMT 回放的旧事件当作当前信号。没有绝对日期或亚秒精度的时间只用于显示诊断，不参与状态更新、下单或延时计算，也不保留原始行情。
- 每只股票最多保留最近 200 条已收到且去重的涨停价买入 `l2order`，作为下单前历史队列。策略下单条件独立决定是否提交委托；回溯本机接收时间最近 2 秒且事件时间不晚于决策时点的记录，只决定是否还需通过后续观察判断撤单。若已有 2 笔不同委托各不低于 150 万元，本次委托照常提交且不因跟随观察不足而撤单；否则这些历史记录与决策后的新事件共同参与 150 笔上限，决策后的新事件还必须有严格晚于决策时点的事件时间。触发委托、重复委托、旧记录和无有效事件时间的记录不作为跟随大单；本策略委托号已关联后，匹配的 L2 事件会排除。
- 竞价期间只更新初始化所需的状态，不产生连续竞价信号。
- 09:25:00 至 09:25:05 每秒批量重试 `get_full_tick`；无效快照不会阻塞整池运行。
- 连续竞价启动时先检查 `get_full_tick` 快照，之后由有效 `l2quote.lastPrice < last_close` 触发负涨幅退出；累计当日最低价不用于这项筛选。可计算的行情延时超过 1000ms 时忽略该负涨幅信号，避免用积压行情永久退出监控。命中后标记为 `SKIPPED_NEGATIVE_RETURN`，取消该股票的 `l2quote`、`l2order` 订阅并停止内部委托验证/查单定时器。已有委托不撤销，策略忽略它之后的委托和成交回报。

连续竞价中启动时，第一条有效 `l2quote` 若已在涨停价，实例进入 `WAIT_REOPEN`，从启动后重新观察封板、开板和回封；若未在涨停价，实例进入 `READY`，后续涨停才可进入首封路径。这样不会把启动前已经发生的封板持续时间或大单累计伪装成可验证的首封。

## 撤单后补单

`RESEAL_VALIDATION_CONTINUE_ON_FAILURE` 默认为 `False`。验证委托撤单确认且没有成交后，策略结束该股票的当日流程，不提交撤单后的跟随单。设置为 `True` 才启用原有的补单条件；首封/回封的首次委托和验证撤单流程不受此开关影响。

## 交易回报

实盘开关开启且通过账号检查后，脚本在订阅回调中以 `quickTrade=2` 提交限价买单。验证在下单决策确定、`passorder` 调用前开始；系统委托号优先解析 `m_strOrderSysID` / `order_sysid`，缺失时按 `get_trade_detail_data(..., "order")` 分片查询，只接受唯一备注令牌匹配或策略名包含该令牌的委托。部分成交后继续监控未成交余量，验证失败时撤销余量；已成交部分不再提交跟随单。`order_callback(ContextInfo, orderInfo)` 和 `deal_callback(ContextInfo, dealInfo)` 只更新全局实例，不把状态挂在回调参数上。首封及回封验证撤单调用 `cancel(order_id, account_id, account_type, C)`。

## 当前差异和后续工作

以下内容来自原设计，但当前脚本仍需独立验证或补齐，后续修改必须先补测试和日志证据：

- 原设计要求的“开盘涨幅低于 3.5%”筛除尚未形成独立计算路径；当前按连续竞价 `l2quote` 最新涨跌幅筛除。
- 当前入口不保存原始行情；`post_order_30s_orders.csv`、前后相邻委托和队列汇总报告仍未生成。
- 策略默认已只保留 `l2quote` 和 `l2order`；完整 L2 周期只在独立诊断探针中启用。
- 需要在真实交易时段继续验证 QMT 对每个 L2 周期的回调字段、回调频率和行情时间戳；策略自身不再测量原始 JSONL 写盘延迟。

## 调试观测

`DEBUG_SUMMARY_INTERVAL_SECONDS` 为 60 秒。`init` 输出股票池交易日和数量；订阅阶段逐项输出返回的订阅号和成功/失败计数。每个周期的第一条行情只输出一次 `[回调首条]`，原始行情不保存。延时优先使用 QMT 的 `time` 时间戳，策略时段判断仍使用 `stime`。新鲜度入口上限为 `l2quote` 3000ms、`l2order` 2000ms，延时告警仍分别为 2000ms、1000ms；周期汇总按告警阈值显示有效样本/总样本数、超限次数、平均/最大/最近延时，以及逐股票聚合的回调间隔均值/最大值。仅对有绝对日期且具备亚秒精度的事件时间计算延时；缺少时间或事件时间晚于接收时钟的样本不纳入延时统计。该观测只读，不改变下单金额/数量阈值、账户或隔夜策略。
