# 大 QMT 隔夜涨停买入原生模型

## 行为

当日输入配置在入口常量 `PLAN_TRADE_DATE` 和 `ORDER_PLAN` 中。计划支持 `(stock_code, amount)` 二元组或含 `stock_code`、`amount` 的字典；交易日必须是 `YYYYMMDD` 且匹配本机日期。默认日期和计划均为空，未配置或计划无效时模型停止。QMT 升级后不再从模型中读取 CSV 或其他文件。价格预检优先使用交易日匹配当天的 `UpStopPrice`（证券资料或全推快照）。资料仍停留在上一交易日时，模型读取该交易日对应的上一收盘价：优先使用日期与资料日一致的全推 `lastPrice`，否则读取未复权日线 `close`，并验证日期一致；随后按证券板块和主板 ST 规则计算到分。新上市保护期、缺少证券名称/上市日期、无法识别板块、收盘价日期不匹配或行情不可用时，模型不猜价格并继续重试，直到准备截止后整批中止。股数按预算除以涨停价向下取整至 100 股。任何计划、价格、整手或可用资金检查失败，整批都不会发单。

启动后按最多 5 行为一片处理价格预检；首轮提交在一个调度回调中连续发送整批委托，最多 500 笔。计划行和失败原因随预检分片输出，末尾只打印汇总。模型不使用线程、线程池、`sleep` 或回调参数保存状态。`init`、定时器和交易回调间的状态保存在脚本全局容器。当前日显式涨停价必须带有当天日期；上一日资料的 `UpStopPrice` 不会作为当天价格使用。计算路径使用 QMT 未复权前收和标准 A 股日涨幅规则，距离证券 `OpenDate` 不足 30 个自然日时必须取得当天显式涨停价，以回避 IPO 无涨跌幅限制阶段。价格、日期或规则信息未就绪时按 500ms 间隔重试；其他价格、整手或计划错误会停止整批。预检日志记录代码、名称、价格来源、参考日期、前收、涨幅和计算涨停价，供盘前核对。

所有股票价格、数量和估算金额预检须在目标提交时间前 `SUBMISSION_PREP_LEAD_MS` 完成；之后复核可用资金、完成批次保留，并提前生成首轮委托的 token、参数和回调映射。目标提交时间由 `SUBMIT_HOUR`、`SUBMIT_MINUTE` 和 `SUBMIT_OFFSET_MS` 决定，默认 08:30:00；正偏移延后提交，负偏移提前提交。到达目标时刻后调度器只进入提交流程，不再读取行情、计算股数、查询资金或保留批次。若价格预检错过准备截止、最终资金检查失败或准备工作跨过目标时刻，整批停止；目标提交时间后才启动也停止，不追赶提交。策略日志末尾追加毫秒级 `log_time`，`SUBMISSION_ARMED` 的 `time` 字段则记录计划提交时刻。为了避免收盘后补发，15:00 起停止提交。本机 QMT 的订单状态 `57` 表示废单；收到该状态且累计成交量为 0 时，通过 100ms 定时调度最多重试两次（总计最多三次提交），不使用 `sleep`。回调消息为空也会按状态码识别。若订单已有成交或成交状态不确定，则不重试，避免重复买入。明确的“未到开市”等拒单文字仅在状态码缺失时作为兼容判据。

QMT 的 `[quote] start simulation mode` 只用于仿真，不代表实盘委托已送达；需要真实委托时必须在 QMT 的 `[trade]` 模式启动模型。

## 安全与状态

- 默认 `ENABLE_LIVE_ORDERS=True`、`ACCOUNT_ID="32011276"`。该设置会调用真实账户；测试必须显式覆盖为模拟账户或关闭实盘。
- 实盘启动先查询 `get_trade_detail_data(ACCOUNT_ID, ACCOUNT_TYPE, "order")`。查询不可用、记录缺少策略身份，或策略名等于本策略名及其 QMT 复合名时，模型在价格预检和下单前停止。当前实现扫描接口返回的全部记录，不按日期过滤；必须先在当前券商 QMT 版本确认查询只覆盖当日委托、`m_strStrategyName` 字段可用。若接口返回历史记录，同策略旧委托会阻止后续运行；若接口漏掉已提交委托，则内存模型无法识别先前运行并可能重复提交。
- 计划、预约标记、attempt/token、订单映射及回调去重状态仅保存在当前模型进程的全局容器中。QMT `passorder` 返回 `0` 时只表示调用没有返回订单号，模型等待异步回报；原生回报备注为空时按股票、价格和数量关联到计划。
- 模型重启后不恢复已提交批次或拒单重试次数。重复运行拦截依赖 QMT 委托查询覆盖完整且只包含目标交易日；不得把离线模拟或空查询结果当作这项保护已在实盘验证。

## 部署

1. 在 QMT “模型研究”中创建独立的原生 Python 模型，不覆盖现有 `QMT_LARGE_ORDER_LIMIT_UP_BUY.py`。
2. 将 `QMT_OVERNIGHT_LIMIT_UP_BUY.py` 作为独立文件部署到 QMT 的 Python 模型目录。
3. 每个交易日更新 `PLAN_TRADE_DATE` 和 `ORDER_PLAN`，核对代码、金额及日期后重新编译入口。
4. 先保持实盘开关关闭，在 QMT `[quote]` 模式检查 `INIT`、`ORDER_PLAN_LOADED`、`PREFLIGHT_OK`、逐行 `PLAN` 和 `DRY_RUN` 日志。
5. 实盘调用需切换到 QMT `[trade]` 模式，并验证 `UpStopPrice`、账户可用资金字段、订单查询返回字段和范围、委托回报状态码及成交量。实盘开关默认开启，启动前核对计划、账户及 QMT 委托页。

## 离线验证

运行：

```text
python -m unittest discover -s strategies/rewrite/overnight_limit_up_buy/tests -v
```

测试只使用模拟 `ContextInfo` 和模拟下单函数，不连接 QMT 账户。
